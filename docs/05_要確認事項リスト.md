# 要確認事項リスト — 店側ヒアリング用

提案書のみで作成したため未確定が多い。**着手前に潰すほど手戻りが減る。** 優先度順（A=着手前に必須／B=設計中に必要／C=運用前まで）。

## A. 着手前に必須（特に給与＝最重要）

| # | 確認事項 | なぜ重要か |
|---|---|---|
| A1 | **雇用形態**（雇用契約 or 業務委託） | 源泉徴収・社会保険・労基法の記載要件・給与か報酬かが全部変わる |
| A2 | **現行Excelの実物と計算式** | 入手できれば給与仕様の大半が即確定。最優先で依頼 |
| A3 | 時給体系（一律／ランク制／個人別）と加算条件（同伴出勤等） | 基本給計算の前提 |
| A4 | 各種バックの**有無・単価・率**（本指名/場内/同伴/ドリンク/ボトル/延長） | 歩合・バック計算の核心 |
| A5 | 歩合率（区分別・スライドの有無） | 同上 |
| A6 | 控除項目（罰金・天引き・送り代・前借り/日払い精算） | 差引支給に直結 |
| A7 | 締め日・支払日・日払いの運用 | 計算期間・前借り精算の前提 |
| A8 | 端数処理ルール（切捨/四捨五入、丸めるタイミング） | 1円単位の不一致＝信頼問題 |
| A9 | ランキングの「pt」定義（売上/指名本数/独自ポイント） | ランキング機能の根幹 |
| A10 | 在籍キャスト数の規模・ピーク時の同時利用 | 性能・コスト見積 |

## B. 設計中に必要

| # | 確認事項 |
|---|---|
| B1 | Excelの列定義・シート構成・1行の粒度（日次/月次） |
| B2 | 申請の種類（欠勤・遅刻・同伴報告・その他）と承認フロー・承認者 |
| B3 | 予約管理の運用（電話予約の入力者、客情報の管理範囲、キャスト紐付け） |
| B4 | 給与明細のCSV/PDF出力の要否 |
| B5 | 源泉徴収票・支払調書の作成をシステムに含めるか（範囲内/外） |
| B6 | 退店者データの保持期間・削除/匿名化方針 |
| B7 | ランキングの公開範囲（順位だけ/ポイントも/上位のみ等）と非公開設定 |
| B8 | 2要素認証/IP制限を管理者ログインに導入するか |

## C. 運用前まで

| # | 確認事項 |
|---|---|
| C1 | 保守の**対応時間帯・SLA**（夜営業＝深夜障害の一次対応をどうするか） |
| C2 | サーバー設置リージョン・ドメイン名の希望 |
| C3 | 初期アカウント発行の運用（誰がキャストにID/初期PWを配るか） |
| C4 | バックアップ世代数・復旧目標（RPO/RTO）の合意 |
| C5 | ブランド素材（ロゴ・金魚イラスト・カラー）の正式データ受領 |
| C6 | 契約面：検収条件・瑕疵対応期間・ソース/データ所有権・著作権帰属・Phase1機能境界 |

## 進め方の提案
A2（現行Excel）を最優先で入手 → A群を1回のヒアリングで確定 → 給与仕様書を確定 → 実装着手。A群が埋まらないうちは画面の「ガワ」とDB土台までに留め、給与エンジンの本実装は保留が安全。
