## 1. 目的・背景

紙・Excel・電話で行っている店舗運営業務（給与計算・売上集計・出勤管理・予約・各種申請）をシステムに集約する。提案書が掲げる6つの価値（競争心アップ／業務自動化／給与計算ミス防止／満足度向上／情報漏洩防止／経営の見える化）を実現する。

特に **給与計算ミスの撲滅** と **機微な個人情報（本名・給与・指名実績）の漏洩防止** を最重要ゴールとする。

## 2. 利用者（ロール）

| ロール | 主な利用者 | 利用デバイス | 概要 |
|---|---|---|---|
| 管理者（オーナー/店長） | 経営側 | PC中心 | 全データの閲覧・編集、Excel取込、承認、ダッシュボード |
| キャスト | 在籍キャスト | スマホ中心 | 自分のデータのみ閲覧、ランキング閲覧、各種申請 |
| ★システム管理者（保守） | Y&Y | PC | 障害対応・バックアップ・アカウント管理（運用ロール） |

権限の原則：**キャストは自分のデータと公開ランキングのみ参照可。他者の給与・本名・売上明細は一切参照不可。**

## 3. 機能要件

### 3.1 管理者用（FOR OWNER）

| ID | 機能 | 概要 | 優先度 |
|---|---|---|---|
| A-01 | Excelデータ取込 | 既存Excel（出勤・売上等）を固定テンプレートでアップロードし取り込む。バリデーション・取込結果プレビュー・エラー行表示・取消（ロールバック）を含む | 必須 |
| A-02 | 店舗ダッシュボード | 当月売上・本日出勤・本日予約・未承認申請件数などをKPI表示 | 必須 |
| A-03 | キャスト管理 | キャストの登録/編集/退店処理、源氏名・基本給与条件・在籍状態の管理 | 必須 |
| A-04 | 給与計算・給与明細管理 | 取込データから給与を自動計算し明細を確定・公開（→ 別紙『給与計算仕様書』） | 必須 |
| A-05 | ランキング管理 | 集計軸・対象期間・公開/非公開を設定し店舗ランキングを生成 | 必須 |
| A-06 | 予約管理 | 予約の登録・確認・変更・キャストへの紐付け | ★中（仕様浅い、要確認） |
| A-07 | 各種申請管理 | キャストからの申請（欠勤/遅刻/同伴報告 等）の一覧・承認/却下 | 必須 |
| A-08 | アカウント/権限管理 | キャストアカウント発行・パスワード初期化・無効化 | 必須 |
| A-09 | 操作ログ・監査 | 重要操作（給与確定・出力・閲覧）の証跡記録 | 必須（セキュリティ要件） |
| A-11 | **実績入力・管理** | 管理者がキャストの実績（出勤時間・本指名/場内指名/同伴・ドリンク/ボトル/延長・売上区分別金額）を**アプリ内で入力・編集**。**アプリを実績の正（source of truth）とし、A-01のExcel取込は「任意の一括投入」に位置づけ**。保存で給与明細・ランキング・ダッシュボードへ即反映。store_idスコープ／キャストは自分の実績は閲覧のみ（編集は管理者） | **必須** |
| A-10 | **設定マスタ管理** | **管理者が画面上で各種数値を設定・編集する。** 時給（個人別/ランク別）・各種客単価/バック単価（本指名・場内指名・同伴・ドリンク・ボトル/シャンパン・延長 等、行追加で独自項目も可）・歩合率（区分別/スライド）・控除設定（罰金・天引き・送り代・前借り精算）・店舗設定（締め日・支払日・端数処理）・ランキングpt定義。**これらの値はコードに固定せず必ずマスタから参照**し、変更は給与計算・ランキングへ反映される（履歴管理＝過去明細は不変） | **必須** |

### 3.3 共通フロー（提案書「システムの流れ」）

`Excel準備 → 管理画面からアップロード → 給与・売上を自動処理 → 本人がスマホで確認`

将来的には Excel手動取込への依存を減らすため、**管理画面からの直接入力（手入力フォールバック）** も用意することを推奨（★要合意）。

## 4. 非機能要件

提案書に記載が無い領域。本システムは機微情報を扱うため特に重要。

### 4.1 セキュリティ
- 通信は全て HTTPS（TLS）必須。
- パスワードはハッシュ化保存（bcrypt/argon2）。初期パスワード強制変更。
- ★ログイン試行回数制限・アカウントロック（総当たり対策）。
- ★管理者ログインの2要素認証（または管理画面のIP制限）を推奨。
- ロールベースアクセス制御（RBAC）。キャストは水平権限分離を厳格に（他人のIDを指定しても閲覧不可）。
- 重要操作（給与確定・データ出力・他者データ閲覧）の操作ログを保存。
- 個人情報の保管場所・暗号化方針を設計指針で定義。

### 4.2 可用性・運用
- ★保守対応時間帯の定義（**夜営業のため障害は深夜帯に発生しやすい** → 緊急連絡フローと対応SLAを契約で明記）。
- 日次自動バックアップ。復旧目標（RPO/RTO）を設計指針で定義。
- 月額保守（税込¥22,000）に含まれる範囲：サーバー利用・監視・障害対応・軽微修正・運用相談（提案書準拠）。**深夜障害対応の扱いは要明記。**

### 4.3 性能・規模
- 想定同時利用：キャスト数 ★数十名規模、管理者 数名。ピークは出勤直後/締め日。
- スマホでの初回表示は体感3秒以内を目標。

### 4.4 互換性・UX
- 対象ブラウザ：モバイルSafari/Chrome 最新、PC Chrome/Edge 最新。
- スマホファースト（キャスト画面）。金額は大きく（44px相当）・本文16pxで可読性確保（モック準拠）。
- レスポンシブ対応。薄暗い店内でも視認しやすい配色。

### 4.5 法令・コンプライアンス
- 給与明細は**労働基準法上の必要記載事項**（支給額・控除内訳・差引支給額等）を満たすこと。
- ★源泉徴収・支払調書の要否を確認（範囲内/外を契約で線引き）。
- 個人情報保護法に則ったデータ取扱い・退店者データの保持/削除方針。
