# 設計指針書 — キャスト管理システム「金魚」

本書は実装（Claude Code）に渡す**アーキテクチャ・技術選定・横断方針**を定める。個別画面仕様ではなく「全体の作り方の指針」。

## 1. 設計原則

1. **最小で確実に。** PHASE 1は単店舗。過剰設計を避けつつ、マルチ店舗だけは後付けが高くつくのでDB段階で織り込む。
2. **機微情報ファースト。** 給与・本名・実績は「見えてはいけない人に絶対見えない」を最優先制約とする。権限はデフォルト拒否。
3. **計算は一箇所に。** 給与・ランキングの計算ロジックはサーバー側の単一モジュールに集約（画面やExcelに散らさない）。再計算可能・監査可能にする。
4. **取込は冪等に。** 同じExcelを二重取込しても壊れない（取込バッチ単位で管理し、やり直し＝洗い替え可能）。

## 2. アーキテクチャ概要

```
[キャスト スマホ/ブラウザ]      [管理者 PCブラウザ]
            \                       /
             \                     /
          [Web/API サーバー (アプリ)]
              - 認証/認可 (RBAC)
              - Excel取込・バリデーション
              - 給与計算エンジン
              - ランキング集計
              - 申請ワークフロー
              - 監査ログ
                     |
              [データベース]  ----  [日次バックアップ]
                     |
              [ファイルストレージ: 取込Excel保管]
```

- 単一のWebアプリ＋API。SPA（スマホUX重視）＋サーバーAPI構成を推奨。
- 認証は自前のセッション/トークン。**キャストと管理者でログイン経路・権限を分離**。

## 3. 技術スタック（推奨・★最終はClaude Code着手時に確定）

提案書の「サーバー込み月額¥22,000・別途クラウド料金なし」という制約に収まるよう、**ランニングコストが軽く保守しやすい**構成を優先。

| 層 | 推奨 | 理由 |
|---|---|---|
| フロント | React + TypeScript（Vite）, Tailwind | スマホUX・モック再現性・開発速度 |
| バックエンド | Node.js（NestJS or Express+TS）／または Laravel(PHP) | 1人保守を想定し情報量の多い枠組み |
| DB | PostgreSQL（推奨）／MySQL可 | 集計・トランザクション・将来拡張に強い |
| 認証 | 自前セッション＋bcrypt/argon2、管理者は2FA任意 | 外部課金回避 |
| Excel取込 | サーバー側でSheetJS等によりパース | フォーマット検証を一元化 |
| インフラ | 単一VPS（国内）＋日次バックアップ | 月額固定・別クラウド課金なしの要件に合致 |
| 監視 | 死活監視＋エラー通知（メール/LINE） | 深夜障害の早期検知 |

> スタックは1案。Claude Codeで着手する際、保守担当のスキルセット（PHP/JS どちらが得意か）に合わせて最終決定する。

## 4. マルチ店舗対応方針（重要）

将来2店舗目以降を想定 → **最初からマルチテナント前提のデータ設計**にする（機能は単店舗でも、構造は複数店舗対応）。

- 全ての主要テーブルに `store_id`（店舗ID）を持たせる。
- ユーザー（管理者/キャスト）は店舗に所属。クエリは常に所属店舗でスコープする（横断アクセス禁止）。
- ランキング・給与・売上の集計は必ず `store_id` 単位。
- PHASE 1のUIは1店舗固定で表示し、店舗切替UIは作らない（構造だけ用意）。

これにより2店舗目展開時はデータ構造の作り直しが不要となり、別見積でも低コストで拡張できる。

## 5. セキュリティ設計指針

- **権限分離（RBAC）：** ロール=管理者/キャスト/保守。キャストのAPIは常に「自分のuser_id＝認証主体」に限定。URLやパラメータでuser_idを差し替えても他人のデータを返さない（IDOR対策）。
- **認証：** パスワードはargon2/bcrypt。初期PW強制変更。試行回数制限＋ロック。管理者は2FAまたはIP制限を推奨。
- **通信：** 全面HTTPS。Cookieは HttpOnly/Secure/SameSite。
- **監査ログ：** 給与確定・明細出力・他者データ参照（管理者の閲覧含む）・ログイン成否を記録。
- **保管：** DBは国内VPS。バックアップは暗号化。退店者データは保持期間後に匿名化/削除（方針は要確認）。
- **最小権限：** 本番DB認証情報・環境変数は秘匿管理。

## 6. 非機能設計

- **バックアップ：** 日次フルバックアップ＋世代管理（推奨7〜14世代）。復旧手順を文書化。RPO=24h, RTO=★数時間 を目安に合意。
- **可用性：** 単一VPSのため計画停止は深夜以外を避ける。障害時の一次連絡フロー（電話/LINE）を運用に組込む。
- **性能：** 集計はバッチ確定＋キャッシュ。ランキング・ダッシュボードは事前計算した値を表示。
- **ログ/エラー通知：** 例外は保守へ自動通知。

## 7. UI/ブランド指針

- ブランドカラー：**金魚レッド `#c8243e`**（モック準拠）。背景は白＋淡い水色グラデ＋波紋。
- 見出しに明朝体「金魚」、ロゴに金魚アイコンでブランド統一。
- 金額は最大級サイズ（44px相当）・本文16px。スマホで片手操作しやすい下部タブ（ホーム/ランキング/出勤/設定）。
- 提案書（黒金・和テイスト）とアプリUI（白ベース）でトーンが分かれるため、**アプリ側のデザイントークン（色・余白・角丸・影）を1ファイルに定義**して統一する。
- アクセシビリティ：コントラスト比確保、タップ領域44px以上。
